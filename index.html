Active Directory Home Lab: Attack Simulation & Detection

SPLUNK · SYSMON · ACTIVE DIRECTORY · MITRE ATT&CK

A SOC lab where I attacked my own Active Directory domain and then wrote Splunk detections for each stage. It follows the MyDFIR lab methodology, extended with my own SPL queries and evidence for every step.

Splunk SPLSysmonActive DirectoryAtomic Red TeamKali LinuxVirtualBoxCrowbar

View on GitHub

What I built

  • Four-machine isolated lab on 192.168.56.0/24: Domain Controller (domain VEL), Splunk server, domain-joined Windows endpoint and Kali attacker
  • Splunk Universal Forwarder and Sysmon on both Windows hosts, sending Security and Sysmon logs into one SIEM index

Attacks and detections

  • T1110.001 Brute Force: RDP password guessing with Crowbar. Splunk showed 48 failed logons (EventCode 4625) for one account, then 2 successful logons (4624): the failed-then-success compromise pattern
  • T1136.001 Create Account: simulated with Atomic Red Team. 14 events correlated across Security 4720/4732 and Sysmon process and registry events
  • The password policy blocked one test account, which confirmed that defensive control worked

What I learned

  • Mapping every attack step to a MITRE technique and a detection query
  • Writing, testing and saving SPL searches (three queries in the repo)
  • Documenting each stage with reproducible evidence, the standard expected in SOC reports

Networking Basics: Cisco Packet Tracer Labs

CISCO NETWORKING ACADEMY · 4 LABS · COMPLETED 19 AUG 2026

A lab portfolio built during the Cisco Networking Basics course. The four labs follow one story: a device joins a network, gets an address, reaches a server, is troubleshot when something fails, and has its web traffic analysed packet by packet.

Packet TracerDHCPDNSHTTPICMP / pingTroubleshooting

View on GitHub

The four labs

  • DHCP on a wireless router: connected 3 PCs, set a custom DHCP range and confirmed automatic addressing
  • Connect to a web server: used ping to verify reachability of 172.33.100.50 and read TTL values
  • Use the ping command: found a misconfigured static-IP PC by comparing it with a working one
  • Observe web requests: followed DNS and HTTP packets in simulation mode

What I learned

  • IP addressing, subnet masks, default gateways, DHCP and DNS
  • A six-step troubleshooting method: symptom, physical links, IP settings, ping, compare with a working device, fix and re-test
  • The base that makes SIEM logs and network alerts readable
